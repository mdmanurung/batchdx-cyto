# L4 — Evaluation metrics (reviewer L4, 2026-10-09)

## Verdict
1. The metric *definitions* are carefully documented and the refusal discipline (insufficient_data / undefined, never 0) is genuinely good; donor-level Stage 8 statistics are statistically sound in design.
2. But the production path (`pipeline.stage_metrics`) computes only the six "common" records; native cyCombine metrics run only identity-vs-identity; the six OpenProblems rows and all Stage 8 preservation are library functions no run ever calls (L4-02, L4-03).
3. Even when called, `emd_mean_ct_horiz`/`emd_mean_ct_vert` score the uncorrected baseline, not the candidate (L4-01) — so two of six "upstream_verified" rows are candidate-invariant.
4. `population_frequency_shift` is also candidate-invariant (L4-04); the only over-correction guards that reach the decision policy are MAD-compression and joint-structure, both pooled-over-samples proxies with uncalibrated thresholds (L4-06, L4-07).
5. No sample/donor-level uncertainty on any metric that feeds the decision (L4-05); the config text still says Stage 8 is "not implemented" (stale).
6. Upstream parity: arithmetic parity of 6 helpers is tested against the pinned helper on shared fixtures (solid); the grouping is adapted (donor/batch substitution) and `upstream_verified` is a hand-set boolean (L4-10). Nine OpenProblems names are reconciled correctly: 6 present, 3 deferred, cms absent upstream — but the FlowSOM deferral reason is stale (L4-09).
7. Gaps vs a complete evaluation suite are substantial (L4-11): no kBET/silhouette/ASW, no label-transfer/classifier over-correction test, no replicate-CV, no rare-population or per-sample structure checks.
8. Net: the "PARTIAL 51/52" and "Stage 8 18/18" gates certify code that is mostly unwired; do not read them as run-level evidence.

## What is solid
- Refusal discipline: thin/undefined cases yield `insufficient_data`/`undefined` with reasons, never 0 (common.py:123-132,231-236; deltas.py:76-94; openproblems.py:413-423,835-847; preservation contrast admissibility).
- `emd_relative_reduction` uses identical comparison sets in numerator and denominator, with no epsilon (deltas.py:56-101).
- Common vs native vs compatibility namespaces are cleanly separated; provenance (label tier, confidence, representation) stamped in one builder (records.py).
- Nine OpenProblems names reconciled exactly once; cms correctly recorded as absent at the pinned commit; the functional-marker rows are honestly described as a retention ratio and an effect-size drift, not Cohen's d/Wilcoxon (registry.py:603-683).
- Stage 8 design: donor-level replicate unit, sorted-level sign convention, blockwise restricted permutation, +1 p-values with Clopper-Pearson, admissibility refusals for confounded contrasts (preservation.py:252-428,664-720).
- Extracted helpers (binned EMD, KDE peak calling, R² dummies, LISI) mirror the pinned code incl. seeds and thresholds, with 1e-9 parity tests on the helper level.
- MAD signed change (vs upstream's unsigned) is a good design choice.
