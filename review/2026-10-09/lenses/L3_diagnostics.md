# L3 diagnostics review (reviewer L3, 2026-10-09)

Scope: `src/batchdx/cyto/diagnostics/*`, `design/audit.py`, `workflow/scripts/cycombine_detect.R`, `cytobatchflagr_detect.R`, and how diagnostics reach `reporting/`. Read-only; no code executed except one hand calculation (Kruskal p-values, shown inline). Literature/field-practice statements are marked *(from memory, to verify)*.

## Verdict

1. The diagnostics layer is honest about its limits: scientific skips are typed (`ineligible` / `not_available` / `failed`), counts of flags are never turned into probabilities, and no detector output feeds the correction recommendation (no `detector` reference in `decisions/` or `metrics/`).
2. Coverage is narrow. Python-native diagnostics are two: within-file drift (per sample x marker) and population-frequency composition. Every marker-wise batch-distance diagnostic (EMD) exists only through R (cyCombine) and only as a table, with no flag, no threshold and no embedded figure.
3. The single statistically weakest component is CytoBatchFlagR's 1.5-IQR fence. The repo itself measured 0.207 false-positive rate per test at four batches (about 0.27-0.30 at 6-20 batches, i.e. it does not improve with n). That figure is in `docs/blocked.md` and a test constant but is NOT in the report or on any assessment, so a reader sees `flag=True` with no error rate and `flag=False` with no hint that "no flag" is weak evidence.
4. Composition is mis-powered at its stated minimum: with 2 samples per batch (the allowed floor) Kruskal-Wallis can never reach p<0.05, yet the detector returns `status="ok"` with no flag. No multiplicity control across populations.
5. Batch-vs-biology confounding is detected only as binary, declared, sample-level, per-factor perfect confounding (`audit.py`). There is no degree-of-confounding measure and no data-driven check (variance in sample medians explained by batch vs biology).
6. Gap vs a "full diagnostics" package is large for pre-correction visualisation (no sample-median PCA/MDS/UMAP, no EMD heatmap, drift plot function exists but is never called), cross-sample run-order/date drift, bead/QC-channel tracking, panel/antibody-lot checks, and any modality-specific logic (the schema has no modality field; spectral unmixing/autofluorescence is declared as a flag only, never checked).
7. No blocker. 6 major, 7 minor, 2 nit (see table). Everything has been validated only on synthetic data (docs/validation_results.md:25-26, :104-109), so no threshold here is calibrated.

## Gap list vs a full diagnostics package (prioritised)

1. Sample-level MDS/PCA/UMAP of per-sample medians coloured by batch and by biology, rendered in Python (L3-04).
2. Marker-wise EMD/KS heatmap with sample-level uncertainty and a technical-reference null (L3-05).
3. Run-order/date drift, anchor/QC and bead-signal tracking over acquisition order; event-rate and time-channel gaps (L3-06, L3-07).
4. Graded batch-vs-biology confounding and variance partition (L3-03).
5. Composition with multiplicity control, CLR handling and honest power gating (L3-02).
6. Panel / antibody-lot / reagent aliasing check (L3-12).
7. Modality-conditioned checks *(from memory, to verify, none of the following is implemented)*: mass (bead-normalisation residuals, signal-decay vs run order, carryover, Gd/Ir DNA channel stability, barcode-debarcode quality), flow (compensation/spillover consistency across batches, PMT-voltage or reference-bead MFI), spectral (unmixing error / residual, autofluorescence signature per batch, reference-control quality, channel-layout compatibility across batches) (L3-11).
8. Per-sample outlier/QC score so that one bad sample is not read as a batch effect.

## What is solid

- Detector status model: `ineligible` / `not_available` / `failed` are distinct and carried to the status table and report; an unavailable R package is never reported as "no batch effect" (`cycombine_detect.py:56-75`, `cytobatchflagr.py:84-122,179-190`; test `test_stage5_detectors.py:168-196`).
- CytoBatchFlagR silent-drop hazard (`min_cells` default, `percent_pos` omission) is found, neutralised and reported as `ineligible` via explicit coverage counts (`cytobatchflagr.py:61-70,192-222`; `cytobatchflagr_detect.R:53-97,171-178`). The wrapper refuses to invent positivity thresholds (`cytobatchflagr.py:126-138`).
- Per-batch identity handling in the R wrapper (batch/control sample ids) is correct and documented (`cytobatchflagr_detect.R:67-74,146-151`).
- Arm's-length GPL integration, pinned commit recorded in the result (`cytobatchflagr_detect.R:29-34,203`).
- Drift is run on full-resolution data per sample, with insufficient-data, zero-spread and missing-order cases typed rather than silently skipped (`drift.py:50-55,70-79,98-106`).
- Composition keeps frequency separate from intensity and names gating/viability/biology as candidate explanations rather than asserting a technical cause (`composition.py:132-151`).
- Design audit: pairwise comparison support classes (reference-supported / conditional / non-identifiable / descriptive), per-population comparisons, reference-graph connectivity, eligibility rules with stated origins (`audit.py:43-115,173-291`).
- Report is not filtered by detector name/namespace: flagged and unflagged assessments are both shown with a "no threshold" note (`html.py:238-296`; template `:302-306`).
- The package is open about the lack of calibration and the synthetic-only evidence (`docs/validation_results.md:25-26,104-116,166-167`; `docs/blocked.md:232-233`).
