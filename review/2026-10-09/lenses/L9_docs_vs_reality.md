# L9 — Docs vs reality

Scope: README.md, RELEASE.md, CHANGELOG.md, docs/{usage,compatibility_matrix,upstream_audit,validation_results,blocked,implementation_status,README}.md, docs/decisions, docs/plans, docs/releases, examples/README.md, config/README.md, THIRD_PARTY_NOTICES.md, ENVIRONMENTS_INSTALLATIONS.md (working-tree versions). Reviewed by reading docs and checking code/tests/config; no tests were executed.

## Verdict

1. The status-bearing documents (README header, RELEASE.md, blocked.md, validation_results.md, generated status) are honest about scope: synthetic-only, uncalibrated, alpha, container/SLURM unrun. No finding contradicts that.
2. The main weakness is drift between documents. Five documents carry pre-2026-09-29 statements that the same repo now contradicts: docs/usage.md §10, docs/upstream_audit.md, docs/compatibility_matrix.md, the `docs/validation_results.md` float64 tolerance, and README:131.
3. "Verified against pinned upstream" is true for the parity tests (helper vs local arithmetic). It is silent that those six OpenProblems functions, and the Stage 8 preservation metrics, have no caller in `src/` or `workflow/` (L1-01, L4-03). README:14-16 and THIRD_PARTY_NOTICES read as if the benchmark scores candidates. This is the most consequential doc-vs-reality gap.
4. `docs/implementation_status.md` is "generated" yet is already out of sync with `scripts/gates.yaml` (Stage 8 and Stage 12 `partial_reason` text), and it reports Stages 1 and 11 as NOT RUN. README says "No gate is BLOCKED; several are PARTIAL", which omits the two NOT RUN gates. Test totals (356/355) predate the CI runs cited in RELEASE.md (375-379).
5. Quickstart: the commands are real and the CLI matches (init/validate/diagnose/benchmark/correct/report/info/audit all exist). The README never says R must be built via `scripts/setup_r_env.sh` (it points at an unbuilt Dockerfile), and the example it tells users to run includes a CytoNorm candidate that the docs elsewhere admit cannot fit.
6. No blocker-level doc defect. Majors are stale or misleading text that would misinform a reader about capabilities in either direction. Counts: 0 blocker, 6 major, 12 minor, 4 nit.

## What is solid

- Scope honesty: "synthetic-only", "uncalibrated", "alpha", "container never built", "SLURM untested (two REPLACE_ME values, confirmed)" are repeated consistently on README, examples/README, validation_results, blocked, RELEASE and CHANGELOG.
- Version triple (pyproject, `_version.py`, CITATION.cff) all 0.1.0; `test_release_metadata.py` enforces it.
- CLI vs docs: init/validate/diagnose/benchmark/correct/report/info/audit exist with the documented flags; `correct` requires `--candidate`; `info --json` has the `workflow` key the README one-liner uses; the identity candidate is enforced in `config.py:369-373`; `assert_baseline_unchanged` and `failure_result` exist where README:111-118 says.
- Multi-seed claim "25 tests over five seeds" checks out (5 non-parametrised + 4 tests x 5 seeds); its limits (not a suite-wide sweep) are stated and match `tests/scientific/test_multiseed.py`.
- Test-id counts quoted for preprocessing (30), PeacoQC (17) match the files; B-006 specificity numbers are consistent between blocked.md, compat matrix, CHANGELOG, validation_results.
- `generate_status.py` really refuses PASSED with missing/skipped tests (:80-90), and `blocked_reason` forces BLOCKED; the "status is generated, not hand-written" design is real.
- Licence statements (CytoBatchFlagR GPL-3 arm's length, CytoNorm GPL>=2, MIT own) match THIRD_PARTY_NOTICES, ADR 0003 and the scripts.
- `config/README.md` and `examples/README.md` agree with `examples.py` and `cli.py` (three examples, same file layout, header-only diff caveat stated).
