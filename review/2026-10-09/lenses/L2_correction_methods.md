## Verdict

1. The three shipped backends (none, cyCombine, CytoNorm) are invoked on the correct upstream routes. The honesty plumbing is good:
   ComBat_seq refused, identity transform pinned, FCS round-trip checked, event identity checked, a missing output is never a pass-through.
2. The Python-side contract is better than its enforcement. `reference_layouts`, `required_sample_fields` and `supports_fit_apply`
   are declared but consumed by nothing except the CLI printout (L2-03). Eligibility lives in a separate table in `design/audit.py`
   and in ad-hoc checks inside each backend.
3. CytoNorm does not check that the training controls are the *same material* across batches (`reference_id` is unused) (L2-01). This is
   the most consequential scientific gap in the correction path.
4. Partial correction (CytoNorm unfitted batches, identity clusters; cyCombine single-batch SOM nodes) is returned as `SUCCESS`
   and the decision policy never reads it (L2-02). It surfaces only as report warnings.
5. cyCombine's `anchor` option is declared and non-functional (L2-04), and the design's protected factors are not wired to cyCombine's
   `covar` (L2-05). The manifest's `use_for_clustering` mask is ignored by both backends (L2-06).
6. cyCombine is transductive (fits on all cells including the validation split) but is scored on the same "held-out" validation
   as CytoNorm (L2-07).
7. Test depth for cyCombine is smoke-only (success + "changed"); no covariate-success, anchor or batch-effect-reduction test (L2-08).
8. Gap to a full package is large: no flow-cytometry reference-free method, no bead/EQ normalisation, no replicate-based RUV method,
   nothing for embedding-level integration. The pinned OpenProblems benchmark already lists ~10 method families; batchdx covers 2.
   See the gap section below. Plugging a new backend in is cheap (one file + register + eligibility row), but is a manual 4-place edit.
9. No blockers. Severity counts: 0 blocker / 3 major / 9 minor / 2 nit (plus the gap items, which are roadmap, not defects).

## How a new method is plugged in (assessment)

Mechanics are good: implement `CorrectionBackend` (`adapters/base.py:86-101`), call `register_backend` at import (`base.py:107-109`), add the import to `adapters/__init__.py:9-11`, add every R call to `adapter_calls` in `config/upstream_lock.yaml` (gated by the stage-0 audit, `docs/usage.md:271-276`). Parameters are pinned with explicit accept/reject lists (`base.py:124-144`) which is a strong pattern.

Friction: (a) four manual edit sites (module, `__init__` import, `ELIGIBILITY_RULES` in `design/audit.py`, config example); (b) eligibility is not derived from capabilities (L2-03); (c) the only exchange formats are the binmat matrix (cyCombine style) and one-FCS-per-sample (CytoNorm style), and every method so far also needs the Dataset in baseline scale; (d) the contract is "returns a corrected matrix of the same shape in the same scale": a method that outputs an embedding (Harmony-type), changes event number, or needs raw (untransformed) intensities (bead normalisation) cannot be expressed. (e) No shared R helper for common `colsToUse`/goal/reference handling. Estimated cost for a new matrix-in/matrix-out method: 2-4 days plus a real-data test.

## Gap vs a full-capacity package, ranked by scientific value

Labels: **[repo]** = evidence in this repo / pinned upstream I read; **[memory]** = from memory, to verify.

Implemented now: none (identity), cyCombine (ComBat per SOM node; reference-free, transductive), CytoNorm (reference-based per-cluster quantile splines; fit/apply).

Evidence of community scope: the pinned benchmark `.upstream/task_cyto_batch_integration/src/methods/` lists batchadjust (all/one control), combat, cyCombine and CytoNorm each in no/one/all-controls x to-goal/to-mid variants, gaussnorm, harmonypy, limma_remove_batch_effect, rpca [repo]. So batchdx covers 2 of ~9 families, and only one control/target variant of each (all-controls-to-mid for CytoNorm; no control-count or target variants).

1. **Reference-free flow-cytometry landmark normalisation (gaussNorm / fdaNorm / warping)** - high value. The package's stated scope is mass, flow and spectral, but the only no-reference backend is cyCombine, which clusters then fits ComBat; for flow data with no control sample the design layer has nothing better to offer. gaussNorm is in the pinned benchmark [repo]; fdaNorm (functional-data registration of density landmarks) [memory]. Per-marker, no controls needed, fast, output is same-shape matrix: fits the current contract. Effort 3-5 d (R adapter, binmat route, reuse cyCombine pattern). Caveat [memory]: landmark methods assume comparable population composition; the design audit's protected-factor logic must apply.
2. **Replicate-based RUV (CytofRUV)** - high value, fits the existing design model. It uses technical replicates (same material in several batches) [memory], which is exactly what `reference_role=technical_replicate|anchor` and `shared_reference_ids` encode. The backend would reuse L2-01's connected-reference check. Needs a per-cluster model; effort 4-6 d. Verify the replicate requirements and that the output is a corrected expression matrix in the asinh scale before committing.
3. **Bead / EQ normalisation (CyTOF) and within-run drift correction** - high value for mass cytometry, but it is a *pre-transform* step on raw intensities with bead channels (Finck et al.; implemented in CATALYST/Premessa) [memory]. It cannot be a correction backend under today's contract (input is the already-transformed baseline; `cytonorm.py:11-13`). It belongs in `preprocess/` ahead of the transform and in the diagnosis layer (acquisition_drift already exists). Effort 3-5 d plus a new "raw layer must be kept" requirement in the dataset contract. Spectral analogue: per-lot/day reference-bead or control-particle scaling and unmixing-matrix versioning [memory].
4. **Simple per-batch reference alignment (BatchAdjust / one-control CytoNorm variants)** - medium-high value, cheap. BatchAdjust is in the pinned benchmark [repo] and handles the common "one bridging control per batch" design that the shipped `paired_reference` example currently cannot fit with CytoNorm (`docs/blocked.md:185-186`). Effort 2-3 d. This directly closes a documented limitation.
5. **Bridging/reference-sample CyTOF methods (iMUBAC)** - medium. Uses reference/bridge samples to compute and apply corrections [memory; I am not certain of the mechanism, verify before scoping]. Overlaps with items 2 and 4; defer until those are in.
6. **Spectral-specific handling** - medium, and mostly a *design/preprocessing* gap rather than a missing algorithm: autofluorescence/unmixing drift and tandem-dye lot effects [memory]. The package relies on CytoNorm/cyCombine for spectral data; there is no spectral-specific test of the cofactor, the negative-value range, or the CytoNorm `limit`/spline range on large-range asinh data. Worth a real-data audit (the repo has a public spectral subset, `data/metadata/cytobatchflagr_spectral`) before any new algorithm.
7. **Embedding-level integration (Harmony, scVI, rPCA, limma removeBatchEffect)** - lower value for this package. harmonypy/rpca/limma are in the pinned benchmark [repo]. limma `removeBatchEffect` is matrix-in/matrix-out and cheap (1-2 d) but linear and applied per marker; Harmony/rPCA/scVI return embeddings or graphs [memory], which the current "corrected matrix in the same scale, exported as H5AD/FCS" contract cannot carry. Needs a new result type and metric path (embedding metrics exist in the openproblems namespace, e.g. iLISI/cLISI). Effort 4-6 d for contract change, 1-2 d per method after that.
8. **Parameter and variant coverage for what exists** - cheap wins: CytoNorm `goal`/`limit`/`colsToUse` (L2-06, L2-13), cyCombine `norm_method` allowed set and `ref_batch` tests, validation of `norm_method` against `{scale, rank, CLR, ...}` (upstream `match.arg` will only fail at runtime). Effort 1-2 d total.

Fit/apply to unseen batches is another capability gap: cyCombine has none (`cycombine.py:62-63`, upstream returns a table, not a model); only CytoNorm can freeze a model. A "correct a new batch against a frozen model" workflow is advertised nowhere, which is consistent with the docs.

## What is solid

- Parameter discipline: pinned defaults serialised into the spec; unknown and refused parameters raise (`base.py:124-144`); ComBat_seq refused in both Python and R (`cycombine.py:81-86`, `cycombine_correct.R:24-28`).
- Correct cyCombine route: `normalize` -> `create_som` -> `correct_data(df, label=labels)` on the un-normalised data, same as the upstream recipe; ordering recovered by `id` and verified (`cycombine_correct.R:51-96`; upstream normalize re-sorts by `id`, `02_batch_correct.R:97-109`). A requested covariate that is missing is refused rather than dropped (`cycombine.py:133-145`).
- CytoNorm route is right and carefully defended: identity transform pinned (and refused in R), training on measured controls in the training split only, leakage check on donor/biospecimen against the validation split, per-sample FCS with an in-band event-identity channel, float32 round-trip proven before CytoNorm runs, missing/reordered/non-finite output refused, unfitted batches derived from the model's actual spline keys, and the `auto_unbox` single-string trap handled (`cytonorm.py:106-121,236-288,336-372,578-614`; `cytonorm_correct.R:167-190,208-212`).
- Failure handling: R exit != 0 -> typed `BackendError` with the log tail; missing package/interpreter -> `BackendNotAvailable`; the pipeline keeps `failed`, `not_available`, `ineligible` distinct and records an exploratory override before running (`pipeline.py:281-339`).
- GPL boundary respected: CytoNorm and CytoBatchFlagR are called in a separate process, never vendored (`upstream_lock.yaml:51-63,91-107`).
- Upstream lock is specific (commit, licence, `adapter_calls`) and the audit gate exists.
- Identity backend is a real candidate that goes through the same validate/score path (`identity.py:1-6,63-71`).
