# L7 - Workflow, containers, HPC, reproducibility

Reviewer L7, 2026-10-09. Repo HEAD b313006 plus uncommitted doc edits. Read-only; no snakemake, docker or sbatch run. Everything below is static reading of the cited lines; nothing was executed.

## Verdict
1. The Snakefile DAG is sound at the structural level. The roster is static, rules are thin calls into `pipeline.py`, and a scientific skip is a successful rule. Parse-time validation of `mode=correct` is good.
2. Rerun/resume semantics have real gaps. Undeclared inputs (dataset files, thresholds file) and undeclared outputs (`corrected.h5ad`, `exploratory_overrides.json`) mean a changed dataset or a deleted h5ad does not trigger a rerun. `log:` is declared on every rule but never written.
3. Byte-stability is plausible. A grep of `src/` for datetime/time/uuid/hostname found no wall-clock in artifacts. The only environment fields (python, platform) sit in `config.resolved.json` and `run_status.json`, not in the analytical fingerprint. I did not re-run the b313006 SVG fix; the claim rests on that grep.
4. Confirmed: the workflow never runs the OpenProblems or preservation metrics. `stage_metrics` calls `compute_common_metrics` plus the native-namespace metrics only (`pipeline.py:394-419`). `compute_openproblems_metrics` and `compute_preservation_metrics` have no caller in `src/` or `workflow/`; the only callers are tests and `metrics/__init__.py`.
5. The container is the weakest part. It has never been built. Beyond that, it probably builds "successfully" with missing packages, because `install.packages` does not fail the layer. It also omits PeacoQC and pbmcapply, which the workflow's R scripts and the conda recipe require, and it ignores the frozen snapshot of the base image.
6. The environment story is fragmented across 6 recipes. The root `pixi.toml`/`pixi.lock` is leftover cookiecutter scaffolding (Python 3.14, no batchdx deps). `renv/` is a 3.7 GB gitignored micromamba prefix, not R renv, and there is no R lockfile.
7. The SLURM profile is explicitly untested and, as written, cannot work as-is. It has REPLACE_ME placeholders, no software-deployment method for the compute nodes, and the CLI offers no way to pass `--profile`.
8. No blockers. Majors are about trust in "reproducible" and "cluster-ready" claims, not about wrong numbers.

## What is solid
- Static DAG expansion from validated config; nothing is inferred from directory existence (`Snakefile:1-10,33-34`; `stage_status` reads explicit result files).
- `mode=correct` requires an explicit, validated candidate at parse time (`Snakefile:36-46`) and again in the CLI (`cli.py:180-182`).
- Report rule depends on results only, so regenerating a report cannot trigger a correction (`Snakefile:250-271`).
- Stage functions are small, read inputs from disk, and write one artifact; scientific skips (ineligible/not_available/failed) are recorded as results rather than rule failures (`pipeline.py:303-339`). Failure types are told apart by exception class, not message text.
- Write ordering for correction (h5ad before JSON) and the baseline-immutability check (`assert_baseline_unchanged`, `pipeline.py:179`) support resume.
- Hashing helpers are canonical (`sort_keys`, separators, explicit float64, shape in the matrix hash, column names in the frame hash) (`io/hashing.py:23-54`); `analytical_fingerprint` excludes cosmetic report config and contains no environment (`config.py:473-482`). No wall-clock calls in `src/` (grep).
- `setup_r_env.sh` is an honest, verifying build: `--vanilla` to dodge a stray `~/.Renviron`, pinned `r-base=4.4`, upstream checkouts verified against the lock by `git rev-parse`, all-or-nothing verification with non-zero exit.
- The local profile is actually exercised: tests pass `--profile` (`tests/integration/test_stage11_workflow.py:52-56`, `test_workflow_resilience.py:65`), and CI runs `snakemake --lint`.
- Status banners on the SLURM profile, Dockerfile and envs README are candid about untested/never-built state; I found no over-claim in them, only stale design.
