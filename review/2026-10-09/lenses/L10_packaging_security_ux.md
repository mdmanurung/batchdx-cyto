# L10 - Packaging, licensing, security, API/UX

Reviewer L10, 2026-10-09. Repo HEAD b313006 plus uncommitted edits. Read-only; no wheel/sdist was built, no code was run except one in-memory `jinja2.select_autoescape` call.

## Verdict

1. The licence position is sound for an MIT package. All five upstream licences in `config/upstream_lock.yaml` match the licence files in the `.upstream` checkouts, and I found no vendored GPL code.
2. The R boundary is clean: argv-list `subprocess.run`, no shell, params passed as JSON, `yaml.safe_load` everywhere. I found no command-injection path.
3. One real security/privacy defect: the HTML report is rendered with Jinja autoescape OFF (L10-01), although the report is built to be circulated.
4. The redaction story is weaker than its docs claim: constant salt, the identifier map sits next to the report, filenames are kept, and the ID replacement is order-dependent (L10-02, L10-03).
5. Licence notices are incomplete for the R packages that actually run (PeacoQC is GPL-3+, FlowSOM and kohonen GPL-2+) (L10-04).
6. The repo still carries a full cookiecutter template, its CI and its pixi tasks. These are not shipped in the wheel but they confuse the repo's own CI and tooling (L10-05).
7. The CLI is serviceable but has gaps: late config validation, an undocumented exit-code map, `init` that silently overwrites, and an `audit` command that cannot work from an installed wheel (L10-07).
8. Python 3.10/3.11/3.13 are declared but never executed (L10-06). No timeouts on R calls (L10-08). Supply-chain pinning is good for source checkouts and weak for CI tooling and Python deps (L10-09).
9. Net: no blocker. 1 major, 9 minor, 3 nit. Nothing here invalidates scientific results.

## What is solid

- Licence accuracy: the cyCombine, CytoNorm, CytoBatchFlagR, OpenProblems and SPiSCy licences in the lock match the `.upstream` checkouts (`DESCRIPTION` and `LICENSE` read). The cyCombine, CytoNorm and CytoBatchFlagR GPL/MIT boundaries are respected: separate Rscript processes, nothing vendored, and ADR 0003 exists.
- The MIT `LICENSE` and the PEP 639 `license`/`license-files` fields are consistent. The `hatchling>=1.27` floor is documented with a reason. The sdist deliberately includes CITATION.cff and THIRD_PARTY_NOTICES.md.
- Upstream sources are pinned by full commit SHA in the lock, `fetch_upstream.sh`, the Dockerfile and CITATION.cff (checked HEAD of each checkout equals the lock).
- No `shell=True`, `eval`, `exec`, `pickle` or unsafe YAML in `src`; `yaml.safe_load` throughout. The R boundary uses an argv list.
- Redaction is on by default and paths are rewritten against the run base, not the cwd. The report path keys are an explicit enumerated list (`CONFIG_PATH_KEYS`), not pattern-matched.
- The CLI delegates to Snakemake rather than reimplementing it, `correct` forces an explicit candidate, `info --json` is machine-readable, and `paths.py` finds assets from either an install or a checkout.
- Disclosure habits: classifiers say Alpha, the Python-version gap and the Dockerfile "never built" status are stated in the files.

- Dockerfile, pixi and environment fragmentation are in L7's scope and only touched where supply-chain pinning is concerned.
