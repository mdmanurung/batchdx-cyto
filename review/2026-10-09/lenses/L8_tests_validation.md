# L8 - Tests, CI and scientific validation (reviewer L8, 2026-10-09)

Read-only review. The test suite was NOT run; `pytest --collect-only` could not run (the `pytest` on PATH has no `_pytest`), so test counts below come from a static regex of `def test_` names against `scripts/gates.yaml` and the committed report numbers.

## Verdict

1. The suite is large (373 defined tests, ~25 files) and is honest about what it is: synthetic-only, uncalibrated, single-seed for Stages 7-9. Disclosure is good; the problem is what the green gates are allowed to imply.
2. A gate turning PASSED/PARTIAL proves only that named test IDs ran without failing. It does not prove the claim is reachable from the CLI/Snakefile. Stage 7 "51/52" and Stage 8 "18/18" exercise `compute_openproblems_metrics` / `compute_preservation_metrics`, which `pipeline.py` never imports.
3. The only recommendation path ever tested is an oracle: `fixture_offset_removal` subtracts exactly the additive per-batch shift the simulator injected, on iid Gaussian cells with no donor-level variance. No real method (cyCombine, CytoNorm) is ever driven through metrics -> decision in a test that asserts a score or state.
4. At least two "fail-closed" style tests cannot fail (L5-03 confirmed from the test side), and one test named for unequal sample sizes asserts a hard-coded constant.
5. The eight tests that do the multi-seed sweep are in no gate, so the Stage 12 gate ("4/4") does not contain them.
6. CI is well-built for an alpha (R env via micromamba, pinned upstream commits, status-doc staleness diff), but its last full run was red, the committed status document was generated from a non-slow run and cannot match a full CI run, and CI is Python 3.12 only.
7. Real-data validation: public Zenodo spectral controls were downloaded, hashed and audited; nothing downstream consumed them, no test touches `data/metadata`, and the subset (technical controls, no donors) cannot test Stage 8 or the decision layer even when used.
8. Counts: 0 blocker, 7 major, 7 minor, 1 nit (15 findings). Severity is capped at major because every limit is disclosed in docs/validation_results.md, RELEASE.md and docs/blocked.md; the issue is gate semantics and evidence strength, not concealment.

## What is solid

- Skips are visible, reasoned and never `xfail`; backend-absent paths assert `not_available` with a stated remedy and refuse to read absence as "no batch effect" (test_stage5_detectors:168-196; test_cytobatchflagr_backend:397-450).
- Gate machinery fails closed in the right direction: a missing gate test becomes `NOT RUN`, a skip becomes `PARTIAL`, a blocked reason overrides PASSED (generate_status.py:73-90), and every gate ID in gates.yaml resolves to a defined test (static check: 0 dangling IDs).
- Good negative-control design where it exists: composition-only change must not move within-population EMD (to 1e-9, test_stage7_metrics:~150-195), joint-scramble preserves marginals exactly but is caught by the joint metric, and the CytoBatchFlagR shifted-vs-clean differential on the same data.
- Multi-seed file has non-vacuity guards (different seeds give different data; the draw cap forces a real subsample; fingerprint changes with seed) and it caught a real provenance bug.
- Upstream parity tests import the pinned reference helper and compare at 1e-9 to exact; Stage 0 audit tests fail the build on commit mismatch or an unverified `compatibility` row.
- Stage 11 e2e tests execute the real workflow (not a dry run), including no-op rerun, invalidation on config change and deletion recovery; no `|| true` hiding failures.
- CI builds the R environment and fails the step if a required package is missing, rather than letting it become skips; R exchange suite (101 assertions) runs in CI.
- Release docs state the synthetic-only limit on the face of README/examples/validation_results; RELEASE.md keeps unverified boxes open.
