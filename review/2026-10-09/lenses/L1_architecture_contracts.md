# L1 — Architecture and contracts

Reviewer L1, 2026-10-09. Repo HEAD `b313006` plus uncommitted doc edits. Read-only static review: nothing was executed, so every runtime claim below is inferred from code (marked in the confidence column). Judged against the goal of a COMPLETE package with full diagnostics and full correction capacity.

## Verdict

1. The skeleton is sound: strict pydantic contracts, a protocol plus registry for backends and detectors, status enums that separate "failed" from "not available", and R isolated behind subprocesses with a typed float64 binary exchange. The central design ideas are good and mostly implemented as described.
2. The gap is between "implemented and unit-tested" and "reachable from a user run". Two whole evaluation families (OpenProblems compatibility metrics and Stage 8 biological preservation, about 2,100 LOC) have no caller in `src/` or `workflow/`, and the recommendation policy reads only three hard-coded metric names (L1-01).
3. The native cyCombine metrics are computed only for the identity candidate against itself, so they never score a real correction (L1-02).
4. Failure handling is weaker than ADR 0006 states: output-validation and other non-`BackendError` exceptions escape `stage_correct`, crash the rule and leave no `failed` record (L1-03).
5. The R to Python boundary is typed on the way in only. R results are free-form dicts, and the defence against jsonlite single-value collapsing exists in two of five consumers. Three consumers still iterate a bare string character by character (L1-04).
6. Contract versioning is declared but not enforced on read, and several run artifacts sit outside the contract set (L1-05).
7. Extension is possible but needs edits in 4 to 6 places with no consistency test. Metrics are not plug-in, and the config surface lacks detector thresholds, policy thresholds, preservation contrasts and per-backend threads (L1-07 to L1-09).
8. Counts: 0 blocker, 4 major, 8 minor, 3 nit. No blocker found. Nothing was executed, so all runtime behaviour is by reading.

## What is solid (with evidence)

- **Strict contracts.** All seven contracts forbid extra keys, validate on assignment and round-trip through JSON; `all_contracts()` is tested for the exact set (`schemas/contracts.py:30-33,433-444`; `tests/unit/test_contracts.py:36-46,59-71`). Enums separate `success/ineligible/failed/not_available` (`schemas/enums.py:75-81`) and the correction/status distinction is carried into `stage_status` (`pipeline.py:512-526`).
- **R isolation.** Subprocess per call with `--vanilla`, a non-zero exit becomes `RScriptFailed` with the log, and `RNotAvailable` is distinguished from a method failure (`r_runner.py:117-139`; `cycombine.py:203-212`; ADR 0002). `BackendNotAvailable` as a type rather than a message match is a good decision, and the ordering in `pipeline.py:317-339` is correct for that case.
- **Event identity.** cyCombine verifies row ids and column names on return (`cycombine.py:193-200`). CytoNorm carries a dedicated identity channel and refuses unverifiable output (`cytonorm.py:12-27,452-465`). Non-finite R output is refused on both sides (`cycombine_correct.R:99-101`).
- **Binary exchange.** Little-endian float64 with a sidecar, `readBin` only, shape checks on write (`binary.py:28-35`) and on read (`binmat.R:22-24`), and a bidirectional R test (`test_contracts.py:99-153`). The R unit tests also pin the length-one `auto_unbox` case for the sidecar (`tests/testthat/test-binmat.R:89-103`).
- **Config strictness.** `extra=forbid` everywhere, removed and pinned keys named with reasons (`config.py:46-135`), and a test that walks the schema to catch accepted-but-ignored keys (`config.py:15-17`). Parameter resolution rejects unknown and refused backend parameters (`adapters/base.py:124-144`). An identity candidate is mandatory (`config.py:369-373`). The rejected-key design is honest about unfinished features (`config.py:85-100,129-134`).
- **Stage structure.** Each stage reads typed inputs from disk and writes one artifact, and the Snakefile rule bodies are one-line calls into `pipeline.py` (`Snakefile:1-5,83-85`). The static roster comes from the validated config, not from directories (`Snakefile:33-34`; `pipeline.py:494-503`).
- **Honest eligibility.** Method constraints carry cited origins (`design/audit.py:41-110`), and the exploratory override is recorded before the backend runs, with a warning attached to the result (`pipeline.py:284-315`).
