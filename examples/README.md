# Examples

Every example is materialised by the CLI, data included, so nothing here depends on a
path that exists only on a developer's machine:

```bash
batchdx-cyto init my_project --example paired_reference
batchdx-cyto init my_project --example no_reference
batchdx-cyto init my_project --example confounded
```

Each writes `data/preprocessed.h5ad`, `config/samples.tsv`, `config/markers.tsv`,
`config/processing.json`, `config/thresholds.tsv`, `config/config.yaml` and a `README.md`
with the exact commands to run. The configuration written holds the same keys with the
same values as the corresponding file in `config/` (see `config/README.md`), but it is
not a byte-for-byte copy: `init` writes a one-line comment header where the file in
`config/` has a longer one.

| Example | Design | The point of it |
|---|---|---|
| `paired_reference` | 3 batches, a measured reference aliquot in each, balanced case/control, technical offset on CD4 and HLA-DR | the reference-supported path end to end |
| `no_reference` | 3 batches, overlapping biology, no measured technical replicate | evidence is conditional, not reference-supported |
| `confounded` | 2 batches, perfectly confounded with group, no reference | the system must abstain |

## Every example here is synthetic, and this package ships no real data

**All three examples are synthetic fixtures generated by `batchdx.cyto.simulate`. This
package includes no real cytometry data and no real-data example.** A public spectral
control dataset is now downloaded outside Git and a homogeneous technical subset is
audited, but it has not gone through the package workflow. The current examples remain
fabricated; the real-data validation task is recorded in `docs/blocked.md` B-008.

Concretely, that means:

* The numbers these examples produce are **not** a scientific claim about real
  cytometry, about any cohort, or about any instrument. They demonstrate that the
  workflow detects what it says it detects and abstains where it cannot tell a technical
  artefact from a biological difference.
* Every threshold in `GATING_THRESHOLDS` and every recommendation threshold the run
  consults is an **uncalibrated engineering default** chosen to sit inside this
  generator's own scale. None of them is a validated cutoff, and none should be cited as
  one or carried over to real data unchanged.
* The behaviour real data would exercise and these fixtures do not: heavy tails,
  multimodality, marker dropout, instrument artefacts, and genuine spillover
  compensation. Nothing in this repository has been run against any of those.
* A real-data example is outside the `0.1.0` Alpha scope. It is required for the later
  validation milestone; `docs/validation_results.md` §4 states the current limit.

To use your own data, do not modify an example: write your own `config/samples.tsv`,
`config/markers.tsv` and `config/processing.json` over your own
`data/preprocessed.h5ad`, point a configuration at them, and read
`docs/usage.md` for the input contract. The examples exist to show the file layout and
the commands, and the gating table is the one thing worth copying — as a starting point
to re-derive against your own panel, not as a threshold set.
